# Federation registry glossary

Domain terms used in [the system design](docs/design.md). General HTTP, database
and concurrency terminology retains its standard meaning.

## Graphs and artifacts

**Subgraph**:
A GraphQL service's contribution to a federated graph, expressed by its
Federation schema.

**Graph configuration**:
The complete collection of subgraph schemas and artifact-defining configuration
considered together for composition. The collection may be empty.

**Supergraph**:
The composed representation of a federated graph, including the metadata needed
to route operations across its subgraphs.

**Public API schema**:
The client-facing GraphQL schema exposed by the composed graph.
_Avoid_: Supergraph SDL, when referring only to the client-facing type system.

**Supergraph artifact**:
The exact generated supergraph retained for selection by a gateway deployment.

**Known client operations**:
The supplied corpus of client GraphQL operation documents. It does not
necessarily represent all operations or client versions in production.

## Proposals and publication

**Source PR**:
A proposed change in a subgraph's source repository from which candidate
Federation SDL is generated.

**Subgraph source revision**:
The source-code revision declared or verified as the input to SDL generation.
It is distinct from a subgraph publication and from the generated bytes.

**Proposed configuration**:
A candidate graph configuration submitted for evaluation or review.

**Approved configuration**:
A graph configuration accepted into the registry under the configured approval
and publication controls.
_Avoid_: Deployed configuration, active configuration.

**Registry revision**:
An immutable record of an accepted graph configuration and any artifacts
generated from it.

**Subgraph publication**:
An accepted version of one subgraph's schema, provenance and artifact-defining
configuration. Multiple registry revisions may reference the same publication.

**Publication intent**:
The requested registry changes, their preconditions and provenance, kept stable
across retries even when the evaluated registry revision changes.

**Publication receipt**:
A record identifying an accepted publication request, its registry revision,
and the exact inputs and result to which acceptance applies.

## Evaluation and execution

**Validity result**:
The assessment of input validity and, for a nonempty graph, Federation composition
under the selected tools. An empty revision has no successful composition result.

**Compatibility result**:
The assessment of public API and known-operation validity changes between
identified baseline and candidate inputs. Missing required schema evidence makes
the comparison unavailable.

**Observed schema**:
The schema obtained from a deployed subgraph at the time it is observed.
_Avoid_: Approved schema, when describing runtime evidence.

**Activation**:
A gateway's adoption of a selected supergraph artifact for execution.
_Avoid_: Registry acceptance, publication.

**Active supergraph revision**:
The registry revision whose artifact a gateway is currently using for execution.
_Avoid_: Latest approved revision, when describing gateway state.
